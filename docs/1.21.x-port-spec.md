# 1.21.x 対応版作成仕様

## 目的
- `1.21.x` フォルダ内に、Minecraft 1.21 系全体向けの Fabric 版 StackPlus を独立してビルドできる状態で作成する。
- 1.21 系の途中で追加・変更された Minecraft 内部フィールドへ静的リンクせず、1.21 初期版でも `NoSuchFieldError` を起こさない。

## 対象範囲
- 既存の StackPlus の機能を維持する。
- 通常アイテムの最大スタック数を 1000 に拡張する。
- vanilla でスタック不可の装備、ツール、武器、盾、バンドル、シュルカーボックスなどは原則 1 個上限を維持する。
- ベッドは既存仕様どおり 1000 個上限にする。
- `1.21.x` フォルダを独立した Gradle/Fabric プロジェクトとして構成する。
- ビルド対象は 1.21 系の下限に寄せ、1.21 系後続パッチで維持されている API だけを直接参照する。

## 制約
- 有料 API、外部有料サーバー、秘密情報は使用しない。
- 既存ルートおよび `stackplus-26.1.x Fabric` の内容は不要に変更しない。
- Fabric の 1.21 系安定版として確認できる最新パッチ版をビルド対象にする。
- `fabric.mod.json` の Minecraft 依存範囲は 1.21 系を示す。
- `Item.ENTRY_CODEC` のように 1.21 初期版へ存在しないフィールドは直接参照しない。
- CODEC 全体を再構築するのではなく、vanilla の `ItemStack` CODEC 初期化に含まれる個数検証上限だけを差し替える。

## 受け入れ条件
- `1.21.x` フォルダ内で Gradle ビルドが成功する。
- 生成される jar 名が 1.21.x 版だと分かる。
- `fabric.mod.json` の Minecraft 依存範囲が 1.21 系になっている。
- 既存のスタック上限変更ロジックが 1.21 系でコンパイルできる。
- `ItemStack` を対象にする Mixin はクラス mixin として定義し、起動時の target type mismatch を起こさない。
- creative インベントリ操作で 1000 個スタックを送信しても、serverbound `set_creative` の `ItemStack` パケット検証で切断されない。
- 1.21 初期版に存在しない `net.minecraft.item.Item` の `field_54952` を参照せず、1.21.9 未満の実行環境でも `NoSuchFieldError` を起こさない。

## 対象外
- Minecraft 1.20 系以前、1.22 系以降への対応。
- ゲーム内での長時間動作確認。
- Mod 機能の追加や UI 変更。
