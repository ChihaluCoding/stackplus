# StackPlus 1000スタック対応仕様

## 範囲
- 通常アイテムの最大スタック数を 1000 個に変更する。
- スロット投入時の上限判定も 1000 個に合わせる。
- チェストなどのコンテナ保存時の上限判定も 1000 個に合わせる。
- チェストなどのコンテナをワールド保存・再読み込みしても 1000 個スタックを維持する。
- クライアントのアイテム個数表示は 1000 個以上を K 表記にする。
- クリエイティブのスロット設定パケットでも 1000 個の ItemStack を受け付ける。
- ベッドは既存方針どおり通常アイテムと同じ上限にする。
- 装備、ツール、武器、盾、バンドル、シュルカーボックスなど、元の最大スタック数が 1 のアイテムはスタック不可のまま維持する。
- README、Mod メタデータ、初期化ログ、バージョンを 1000 個仕様に合わせる。

## 制約
- 既存の mod ID、パッケージ構造、Mixin 構成は変更しない。
- 設定画面やコマンドなど、ゲーム内で上限を変更する機能は追加しない。
- API キー、外部有料サービス、外部サーバーは使用しない。
- 既存の未コミット変更は維持する。

## 受け入れ条件
- `StackLimitConfig.STACK_LIMIT` が 1000 である。
- 通常アイテムとベッドの最大スタック数が 1000 になる。
- 通常アイテムをスロットに置く時も 99 個で止まらず 1000 個まで入る。
- 通常アイテムをチェストなどのコンテナへ入れても 99 個に丸められない。
- 通常アイテムをチェストなどのコンテナへ入れてワールドに入り直しても、アイテムが消えず 1000 個まで維持される。
- 1000 個のスタックは GUI 上で `1K` と表示される。
- 1000 個の通常アイテムをスロットに置いても `set_creative_mode_slot` の decode 例外で切断されない。
- 元の最大スタック数が 1 のアイテムは 1 のままになる。
- `./gradlew.bat build` が成功する。

## 対象外
- サーバー専用 mod 化。
- アイテム別の上限設定。
- UI 表示形式の独自描画。
